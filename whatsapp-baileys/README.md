# خدمة واتساب (Baileys) لأداة Guide

خدمة Node صغيرة تربط **رقم واتساب واحدًا** بمسح رمز QR، وتُرسل رسائل الاشتراك التي
تولّدها أداة Guide. تعمل كحاوية مستقلة، وتتصل بها الأداة عبر قناة **«بوابة HTTP خاصة»**.

> تنويه: Baileys غير رسمي وقد يُعرّض الرقم للحظر من واتساب. استخدم رقم عمليات مخصّصًا.

## الواجهة

| المسار | الطريقة | المصادقة | الوظيفة |
|---|---|---|---|
| `/health` | GET | — | صحّة الخدمة |
| `/` | GET | `?key=` | صفحة مسح رمز QR للربط |
| `/status` | GET | `?key=` أو Bearer | `{connected, me, hasQR, inbound}` |
| `/qr` | GET | `?key=` أو Bearer | `{connected, qr}` (صورة data-URL) |
| `/send` | POST | Bearer | `{to, text}` → يرسل ويرجّع `{ok, id}` |
| `/logout` | POST | Bearer | يفصل الجلسة لإعادة الربط |
| `/fake-inbound` | POST | Bearer | **بوضع `WA_FAKE` وحده**: `{from, text}` يحاكي رسالةً واردة |

`to` رقم دولي بالأرقام فقط (مثل `9665xxxxxxxx`)؛ الخدمة تنظّفه تلقائيًّا.

## متغيّرات البيئة

| المتغيّر | الافتراضي | الوصف |
|---|---|---|
| `WA_SECRET` | — | **مطلوب**: سرّ المصادقة (نفس «سر البوابة» في إعداد الأداة). |
| `WA_PORT` | `80` | منفذ الاستماع. |
| `WA_AUTH_DIR` | `/app/auth` | مجلد جلسة واتساب — **اجعله Volume دائمًا** ليبقى الربط بعد النشر. |
| `WA_FAKE` | — | `1` = مُرسِل وهمي بلا واتساب (للاختبار فقط). |
| `WA_FAKE_ME` | — | رقم الخدمة بوضع `WA_FAKE` (بدل «FAKE»). |
| `WA_INBOUND_URL` | — | أين تُمرَّر رسائل مسابقة التوقّعات: `https://guide.ssouq.com/api/contest/wa-inbound`. فارغًا = لا استقبال. |

## النشر على Coolify (خدمة منفصلة)

1. **New Resource ← Application** في نفس المشروع، من نفس المستودع (`qsorry/ssouq-guide`).
2. **Build:** Dockerfile، و**Base Directory = `whatsapp-baileys`** (فمجلّدها وحده يُبنى).
3. **Environment:** `WA_SECRET = «سرّ طويل تختاره»`.
4. **Persistent Storage:** أضِف Volume على `/app/auth` (وإلا يُطلب مسح QR بعد كل نشر).
5. **Domain:** أعطها نطاقًا (مثل `wa.ssouq.com`) أو أبقِها داخلية وصِل الأداة بها بالشبكة الداخلية.
6. انشر، ثم افتح `https://<الخدمة>/?key=<WA_SECRET>` وامسح الرمز من:
   واتساب ← الإعدادات ← الأجهزة المرتبطة ← ربط جهاز.

> لتفادي إعادة بناء تطبيق Guide الرئيسي عند تعديل هذه الخدمة (ومعه انقطاع مؤقّت)،
> اضبط Watch Paths لكل خدمة على مجلّدها.

## الرسائل الواردة: مسابقة التوقّعات
> **لم تعد المسابقة تستعمل هذا المسار:** رقم المسابقة يُربط الآن بخدمة واتساب النظام اللوجستي
> (‏`whatsapp-reader`) من صفحة مدير المسابقة — انظر «مسابقة التوقّعات» في README الرئيسي. اترك
> `WA_INBOUND_URL` فارغًا هنا. وما يلي وصفٌ للخاصية كما هي.

المشارك في مسابقة التوقّعات يسجّل توقّعه برسالةٍ يرسلها إلى **الرقم المربوط بهذه الخدمة**. فالخدمة
تمرّر كل رسالةٍ فيها «رمز التوقّع» إلى `WA_INBOUND_URL` برقم مرسلها (من `remoteJid`، أو `senderPn`
حين يصل المرسل بمعرّف LID) ووقت إرسالها من خادم واتساب، موقَّعةً بـ `Bearer WA_SECRET`، وترسل للمرسل
الردّ الذي تعيده الأداة. **وما عدا ذلك من رسائل العملاء لا يُمرَّر ولا يُردّ عليه**، ولا رسائل
المجموعات والحالات والقنوات، ولا ما أرسله الرقم نفسه. والرسالة التي تصل مرتين تُمرَّر مرة.

فعّلها بضبط `WA_INBOUND_URL` وإعادة النشر؛ و`/status` يعيد `inbound: true`، وصفحة المسابقة في
الأداة تقول إن كان التسجيل جاهزًا.

## الربط بأداة Guide

في **لوحة التحكم الأساسية ← خدمة سلة ← واتساب**:
- القناة: **بوابة HTTP خاصة**.
- الرابط: `https://<الخدمة>/send`
- السر: نفس `WA_SECRET`.
- اضغط **«فحص اتصال واتساب»** للتأكد من أن الرقم مربوط، ثم **«إرسال رسالة اختبار»**.

## التشغيل محليًّا

```bash
cd whatsapp-baileys && npm install && WA_SECRET=dev npm start
# للاختبار بلا واتساب:
WA_FAKE=1 WA_SECRET=dev node index.js
```
