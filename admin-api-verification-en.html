Section A — Panel install domain (root cause)

The panel was installed on one domain, then changed. The old domain mr7-4k.live is still stored in the stream/API settings, so access-code links are built on a domain that does not resolve. Unify all references on the final domain {NEW} (most likely mr7-4k.sbs):

  1. DNS: add an A record for every hostname used (admin + stream + API) in the {NEW} zone ← 205.237.107.54. On Cloudflare, set the stream-port records to DNS only (grey cloud), since Cloudflare only proxies specific HTTP ports (80, 8080, 2052, 2082, 2086, 2095…).
  2. Panel General Settings: update the Panel URL / Access URL / Stream DNS field (used to build access-code and stream links) from mr7-4k.live to {NEW}.
  3. Servers / Load Balancers: for each server, update the Server Domain / DNS field to {NEW}.
  4. nginx: add {NEW} to server_name on the admin and stream ports, with a valid SSL certificate.
  5. Access codes: after the change, open Access Codes and confirm each link now uses {NEW}, not mr7-4k.live (regenerate/re-copy if needed).
  6. Old domain: keep it pointed during the transition, or remove all references to it.
Quick check: every code link on the Access Codes page must show {NEW} and that domain must actually resolve.

Section B — Verify the API setup inside the panel

  1. Access code: Access Codes ← a code of type Reseller API, status Active.
  2. IP list: open the code ← Restrictions tab ← Allowed IP Addresses contains 158.220.81.202 (shown in the list box and saved with Add).
  3. Package groups: the code's Groups tab has the sold package groups enabled, and each package has Bouquets assigned.
  4. Group permissions (Edit Group ← Permissions): Can Use Reseller API ✓, Can Generate Mass Paid ✓, Can Delete Users ✓, User Delete Refund ✓.
  5. api_key: from Manage end-points / API Settings — copy the key tied to the code. (The Admin API Management key is different and will not work.)

Section C — Verify from the server (live test)

Run from our server 158.220.81.202. Replace {NEW}, {PORT}, {KEY}, then copy & paste.

1) Does the domain resolve?

getent hosts {NEW} || nslookup {NEW}

2) Does the endpoint respond? (safe, creates nothing) — action=user_info

curl -sS "http://{NEW}:{PORT}/msAPIufgk/reseller/index.php?api_key={KEY}&action=user_info"

Python fallback if curl is missing:

python3 -c "import urllib.request as u;print(u.urlopen('http://{NEW}:{PORT}/msAPIufgk/reseller/index.php?api_key={KEY}&action=user_info',timeout=25).read().decode())"

3) Read packages — action=packages

curl -sS "http://{NEW}:{PORT}/msAPIufgk/reseller/index.php?api_key={KEY}&action=packages"

4) Dry-run create test (dry_run=1, no real creation)

curl -sS -X POST "http://{NEW}:{PORT}/msAPIufgk/reseller/index.php" -d "api_key={KEY}&action=create_line&package_id={PKG}&dry_run=1"

5) Local test on the panel host itself (bypasses DNS and IP whitelist)

curl -sS -H "Host: {NEW}" "http://127.0.0.1:{PORT}/msAPIufgk/reseller/index.php?api_key={KEY}&action=user_info"

Try the other code resellerapi with the same commands if needed.

Section E — What to send us after success

Once you get a STATUS_SUCCESS response, send us:

  1. The full working URL (final domain, port, and code).
  2. The api_key tied to the code.
  3. The final approved domain and port.

We will then connect the gateway in Reseller API mode directly.
